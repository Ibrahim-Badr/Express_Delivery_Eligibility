# ADR 0001: Initial Infrastructure Adapters (In-Memory / Local vs Database)

**Date:** 2026-10-06
**Status:** Accepted (amended 2026-10-06: added PredictionStore, naming aligned)

## Context
The Express Delivery Eligibility application needs three storage mechanisms:
1. **Order Store:** persist incoming order features before prediction (`POST /v1/orders`, `GET /v1/orders/{order_id}`).
2. **Prediction Store:** keep computed predictions so they can be re-read (`GET /v1/predictions/{order_id}`, session 5) and observed (session 7).
3. **Model Repository:** load the trained pipeline and its Model Card (`/v1/model`) and tell `/health/ready` whether a model is available.

The application layers (`api`, `ml`) only depend on abstractions located in `src/infra/abstractions/` (`OrderStore`, `PredictionStore`, `ModelRepository`). Concrete adapters are chosen in one place: `src/core/dependencies.py`.

## Decision
Implement **Option 1: Simple & Local Storage (YAGNI)** for the first iterations:
- Orders: `MemoryOrderStore` (Python dict in RAM).
- Predictions: `MemoryPredictionStore` (Python dict in RAM).
- Model artifacts: `FileModelRepository` reading `artifacts/pipeline.pkl` and `artifacts/model_card.json`.

The `ModelRepository` port exposes at least: `load_model()`, `load_model_card()`, `is_available()`.

Naming convention: concrete adapters are prefixed by their technology (`Memory*`, `File*`, `Sql*`, `Mlflow*`).

## Consequences
### Positive
- Fast development: no database or MLflow server to provision or migrate.
- No external dependency to run the API or the tests.
- Zero infrastructure cost in development.

### Negative
- Orders and predictions are lost on restart.
- With several workers (`uvicorn --workers N`) each worker has its own memory, so lookups are inconsistent. Run a **single worker** in dev (documented in README).

## Future Migration Triggers
Migrate to a real database (e.g. PostgreSQL, `SqlOrderStore`, `SqlPredictionStore`) when any of these holds:
1. **Horizontal scaling:** several instances behind a load balancer need shared state.
2. **Persistence:** collected data must survive restarts or crashes.
3. **Volume:** data volume threatens to exceed available RAM.

Migrate to MLflow registry (`MlflowModelRepository`) when model versioning/promotion across environments is needed.
Because of dependency inversion, each migration adds an adapter in `src/infra/<tech>/` and changes one line in `dependencies.py`; `api` and `ml` are untouched.
